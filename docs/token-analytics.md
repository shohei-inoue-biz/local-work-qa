# トークン使用量分析：auto-record.sh

`bash scripts/auto-record.sh` を実行したときのトークン消費量を、  
実際の `contexts/` ファイルをもとに分析したドキュメントです。

---

## TL;DR

| 指標 | 値 |
|---|---|
| 平均入力トークン / 回 | **~18,700 トークン** |
| 平均出力トークン / 回 | **~800 トークン** |
| 入力の大部分 | Chrome 閲覧履歴（全体の約 70–80%） |
| 固定オーバーヘッド | 約 2,540 文字（指示 + テンプレート） |

---

## プロンプト構造

`auto-record.sh` が Copilot CLI に渡すプロンプトは以下の 3 部構成です。

```
┌─────────────────────────────────────┐
│ 1. 固定指示（~923 文字）             │  変化なし
│    - 分析方法・保存パスの指定         │
├─────────────────────────────────────┤
│ 2. テンプレート（~1,582 文字）        │  変化なし
│    - templates/problem.md の内容    │
├─────────────────────────────────────┤
│ 3. 作業コンテキスト（可変）           │  実行ごとに変動
│    - Shell 履歴                     │
│    - Chrome 履歴・訪問 URL           │
│    - Copilot CLI セッションログ       │
│    - Codex / Gemini ログ（任意）     │
└─────────────────────────────────────┘
固定オーバーヘッド合計: ~2,540 文字
```

## 実行ごとのプロンプトサイズ計測

`contexts/` に保存された実績ファイルを計測した結果：

| 実行日時 | プロンプト (文字) | コンテキスト (文字) | 固定分 (文字) | 推定入力トークン |
|---|---:|---:|---:|---:|
| 2026-06-17 21:23 | 54,289 | 51,749 | 2,540 | ~21,700 |
| 2026-06-17 21:32 | 58,593 | 56,053 | 2,540 | ~23,400 |
| 2026-06-17 21:35 | 60,217 | 57,677 | 2,540 | ~24,100 |
| 2026-06-18 10:07 | 24,790 | 22,250 | 2,540 | ~9,900 |
| 2026-06-18 19:37 | 36,480 | 33,940 | 2,540 | ~14,600 |
| **平均** | **46,873** | **44,333** | **2,540** | **~18,700** |

> **トークン推定方法**: 日本語・英語混在テキストを 2.5 文字 / トークンとして推定。  
> 正確な値は `tiktoken` や各モデルの tokenizer で確認してください。

## コンテキストのセクション別内訳

コンテキスト全体のうち、各セクションが占める割合：

| セクション | 代表サンプル (文字) | 割合 | 特性 |
|---|---:|---:|---|
| 2. Chrome 検索履歴・訪問 URL | ~16,000–32,000 | **約 75%** | 日ごとに大きく変動 |
| 1. Shell コマンド履歴 | ~4,200 | 約 15% | ほぼ固定（直近 200 件） |
| 3. Copilot CLI セッション | 55–258 | <1% | セッション数に依存 |
| 4. Codex CLI ログ | ~43 | <1% | 未インストールなら固定テキスト |
| 5. Gemini CLI ログ | ~49 | <1% | 未インストールなら固定テキスト |

**Chrome 履歴が支配的**：1 日の閲覧量によって入力トークンが 2 倍以上変動します。

---

## 入力トークンの変動要因

```
入力トークン ≈ (固定: ~1,000) + (Shell履歴: ~1,700) + (Chrome履歴: 可変)
                                                         ↑ここが主な変動源
```

- **Chrome 履歴が少ない日**（例: 2026-06-18 10:07）→ 約 10,000 トークン
- **Chrome 履歴が多い日**（例: 2026-06-17 21:35）→ 約 24,000 トークン

## 出力トークン推定

Copilot CLI が生成する `records/` の問題記録ファイルは  
`templates/problem.md` を埋めた形式になります。

| 出力内容 | 推定トークン |
|---|---|
| problem.md 全フィールド記入 | ~600–800 |
| `update-index.sh` 実行の応答 | ~50–100 |
| **合計（推定）** | **~700–900** |

入力と比較すると出力は 1/20 以下です。

## 他の操作との比較

1 回の `auto-record.sh` 実行（平均 ~19,500 トークン）がどのくらいの規模か：

| 比較対象 | 合計トークン | auto-record.sh との比 |
|---|---:|---:|
| Copilot チャット 1 往復（短め） | ~600 | **1/32** |
| Copilot チャット 1 往復（長め） | ~1,500 | 1/13 |
| 中規模 PR のコードレビュー依頼 | ~6,000 | 1/3 |
| **auto-record.sh 1 回** | **~19,500** | **1** |
| 日本語文庫本 80 ページ | ~19,000 | ≒1 |

> **感覚値**: 「Copilot チャットを 30〜40 往復した分」を 1 回の実行で消費するイメージ。

## GitHub Copilot 利用上の考慮点

`auto-record.sh` は GitHub Copilot CLI のサブスクリプション枠内で動作します。  
Copilot の利用制限（レート制限・月間上限）に対する影響：

| 条件 | 影響 |
|---|---|
| 1 日 1 回実行 | 約 10,000–24,000 入力トークン / 回 |
| 週 5 日実行 | 約 50,000–120,000 入力トークン / 週 |
| Chrome 履歴なし（`--dry-run` 確認後に削除等） | 約 6,000 トークン / 回まで削減可能 |

## トークン削減のアプローチ

### 1. Chrome 履歴をフィルタリングする

`collect-context.sh` の URL 収集クエリに条件を追加：

```bash
# 現在（全 URL、上限 100 件）
"SELECT DISTINCT u.title, u.url ... LIMIT 100"

# 改善例：仕事関係のドメインに限定
"SELECT DISTINCT u.title, u.url ... 
 AND (u.url LIKE '%github.com%' 
   OR u.url LIKE '%docs.%'
   OR u.url LIKE '%stackoverflow.com%')
 LIMIT 50"
```

効果：最大 30–40% 削減（Chrome 履歴が支配的なため）

### 2. 訪問 URL の重複を削減する

同一ドメインへの多数アクセスは検索クエリのみ保持するよう変更することで  
Chrome 履歴セクションを 50% 以上削減できます。

### 3. Shell 履歴の件数を減らす

`collect-context.sh` の `tail -200` を `tail -100` に変更：

```bash
# 現在
tail -200 ~/.zsh_history >> "$OUTPUT_FILE"

# 変更後（~2,100文字削減）
tail -100 ~/.zsh_history >> "$OUTPUT_FILE"
```

### 4. `--dry-run` で事前にサイズ確認する

```bash
./scripts/auto-record.sh --dry-run
wc -c contexts/*-prompt.txt | tail -1  # サイズ確認
```

## 計測方法メモ

```bash
# プロンプトファイルの文字数確認
wc -c contexts/*-prompt.txt

# コンテキストファイルの文字数確認
wc -c contexts/*.md

# セクション別サイズ確認（Python）
python3 -c "
import re
with open('contexts/YYYY-MM-DD-HHMM.md') as f:
    content = f.read()
for m in re.finditer(r'^## \d+\. (.+)\n(.*?)(?=^## |\Z)', content, re.M|re.S):
    print(f'{m.group(1)[:40]}: {len(m.group(2)):,}文字')
"
```
